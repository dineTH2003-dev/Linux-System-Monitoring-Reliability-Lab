## 1. Executive Summary & Root Cause Analysis

During Phase A controlled runtime verification, the custom Python monitoring agent (`127.0.0.1:9101`) demonstrated full operational readiness:
- Python agent started cleanly and exposes valid Prometheus metrics and JSON health responses.
- Socket binding is strictly limited to loopback `127.0.0.1:9101`.
- Container-to-host network routing through `host.docker.internal:9101` succeeded (HTTP 200).
- Prometheus direct scrape succeeded with `health: "up"` and `up{job="python-agent"} = 1`.
- Blackbox TCP probe (`host.docker.internal:9101`) succeeded with `probe_success = 1`.

However, the Blackbox HTTP probe (`http://host.docker.internal:9101/metrics`) reported `probe_success = 0`, despite returning HTTP status 200.

### Direct Empirical Evidence
A direct probe request was executed against the Blackbox Exporter:
```bash
docker exec lab-prometheus wget -S -O- \
  "http://blackbox-exporter:9115/probe?module=http_2xx&target=http://host.docker.internal:9101/metrics"
```

**Captured Exporter Telemetry:**
```text
# HELP probe_http_status_code Response HTTP status code
# TYPE probe_http_status_code gauge
probe_http_status_code 200

# HELP probe_http_version Returns the version of HTTP of the probe response
# TYPE probe_http_version gauge
probe_http_version 1

# HELP probe_failed_due_to_regex Indicates if probe failed due to regex
# TYPE probe_failed_due_to_regex gauge
probe_failed_due_to_regex 0

# HELP probe_success Displays whether or not the probe was a success
# TYPE probe_success gauge
probe_success 0
```

### Root Cause Identification
1. **Blackbox Probe Configuration:**
   In `blackbox/blackbox.yml`, the `http_2xx` module strictly restricts acceptable HTTP protocol versions:
   ```yaml
   valid_http_versions: ["HTTP/1.1", "HTTP/2.0"]
   ```
2. **Python HTTP Server Implementation:**
   The monitoring agent utilizes Python's standard library `http.server.BaseHTTPRequestHandler` in `agent/server.py`. In standard Python (`http.server`), the class-level default attribute is:
   ```python
   protocol_version = "HTTP/1.0"
   ```
   Consequently, every response generated by `self.send_response(status)` emits the header:
   ```http
   HTTP/1.0 200 OK
   ```
3. **Failure Mechanism:**
   Blackbox Exporter validates both the HTTP status code (2xx) **and** the protocol version (`HTTP/1.1` or `HTTP/2.0`). Because the agent responds with `HTTP/1.0`, Blackbox exporter sets `probe_http_version 1` and marks `probe_success 0`, despite valid network reachability, valid HTTP status 200, and complete payload transmission (25,964 bytes).

## 3. Comparison of the Two Possible Fixes

### Option 1: Update `blackbox/blackbox.yml` (Allow `HTTP/1.0` in Prober)
Permit `"HTTP/1.0"` in the Blackbox `http_2xx` module:
```yaml
valid_http_versions: ["HTTP/1.0", "HTTP/1.1", "HTTP/2.0"]
```

- **Architectural Appropriateness:**
  - High. Exporters and internal telemetry endpoints are simple, synchronous request-response interfaces. HTTP/1.0 with explicit `Content-Length` is completely valid, standard, and robust for lightweight telemetry daemons.
  - Blackbox Exporter configuration exists specifically to model and validate the expected behaviors of target services in the environment.
- **Impact on Other Probed Services:**
  - Zero. Native Node Exporter (`:9100`), Prometheus (`:9090`), and Alertmanager (`:9093`) respond with `HTTP/1.1`. They will continue to pass without deviation.
- **Connection & Framing Safety:**
  - Does not touch Python runtime code.
  - No risk of persistent connection concurrency issues or worker thread blocking.
- **Operational Complexity:**
  - 1-line configuration change.
  - Reloadable dynamically via Blackbox Exporter's `POST /-/reload` endpoint without restarting the container.

---

### Option 2: Update `agent/server.py` (Upgrade Agent to `HTTP/1.1`)
Set `protocol_version = "HTTP/1.1"` on `MetricsHandler` in `agent/server.py`:
```python
class MetricsHandler(BaseHTTPRequestHandler):
    protocol_version = "HTTP/1.1"
```

- **Architectural Appropriateness:**
  - Complies with modern HTTP protocol conventions.
  - Makes the agent conformant to default web probers that expect `HTTP/1.1`.
- **Connection Handling & Concurrency Consequences (CRITICAL):**
  - In Python's standard library `BaseHTTPRequestHandler`, setting `protocol_version = "HTTP/1.1"` fundamentally alters connection lifecycle behavior:
    1. **Keep-Alive Default:** In HTTP/1.1, persistent connections are active by default (`self.close_connection = False`).
    2. **Thread Blocking Risk:** `ThreadingHTTPServer` allocates a worker thread per TCP connection. If a client connects with `HTTP/1.1` and does not send `Connection: close`, the worker thread remains blocked in `self.rfile.readline()` waiting for subsequent requests.
    3. **Socket Timeout:** `BaseHTTPRequestHandler` defaults socket timeout to `None`. A lingering or idle client could tie up Python threads indefinitely unless socket timeouts or explicit connection teardowns are enforced.
  - **Mitigation Requirement:** To safely implement `HTTP/1.1` in `agent/server.py`, the response handler **must** explicitly inject `Connection: close` and set `self.close_connection = True` to prevent thread and socket leaks:
    ```python
    self.send_header("Connection", "close")
    self.close_connection = True
    ```
- **Operational Complexity:**
  - Modifies application Python code after baseline verification.
  - Requires stopping and restarting the active Python agent process (`PID 1755348`).

## 5. Recommended Minimal Patch

### Primary Recommendation: **Option 1 (Prober Configuration)**
Option 1 is the cleanest, lowest-risk SRE remediation. Blackbox Exporter is designed to adapt its validation rules to target systems. Permitting `HTTP/1.0` in `valid_http_versions` accurately reflects that internal telemetry daemons use lightweight HTTP/1.0 framing without keep-alive overhead.

#### Proposed Patch for `blackbox/blackbox.yml` (Diff Only):
```diff
--- a/blackbox/blackbox.yml
+++ b/blackbox/blackbox.yml
@@ -9,7 +9,7 @@ modules:
     prober: http
     timeout: 5s
     http:
-      valid_http_versions: ["HTTP/1.1", "HTTP/2.0"]
+      valid_http_versions: ["HTTP/1.0", "HTTP/1.1", "HTTP/2.0"]
       valid_status_codes: [] # Defaults to 2xx
       method: GET
       preferred_ip_protocol: ip4
```
